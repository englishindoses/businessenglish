## The practice app

- **Source:** `app-src/` — Vite + plain JavaScript + `vite-plugin-pwa`. See
  `app-src/README.md` for commands and folder layout.
- **Built app:** `app/` — generated by `npm run build` inside `app-src`, and committed,
  because Pages serves straight from `main`. Never edit `app/` by hand.
- **No GitHub Actions, on purpose.** Switching Pages to an Actions build would change how
  the *whole* site publishes, lesson pages included, so a broken workflow could take the
  lessons down. Build locally and commit the output.
- **Testing on a phone over Wi-Fi:** `npm run dev -- --host` in `app-src`. Installing to
  the home screen only works from the live https URL.

### How the app behaves (decided with the owner)

- Home → choose topic → choose activity → **3 rounds of 4 questions** → review of all 12.
- Four activity types: gap-fill (dropdown), right or wrong, matching (tap to place),
  word order (tap words). Category sorting is parked for later. **No flashcards or
  speaking prompts** — everything is auto-marked with instant feedback.
- The student checks at the end of each round. Wrong answers show a short clue and can
  be edited and re-checked as often as needed. **It's practice, not a test:** a question
  counts as right once it checks green, however many tries it took.
- Checking with blanks opens a dialog: *Finish them* or *Check anyway*.
- Word order reveals the correct sentence after 3 failed checks.
- Review screen: right/wrong for all 12, a link back to the lesson on the site, and three
  ways out — *Try these again* (same 12 questions), *Another activity*, *Choose a topic*.
- **"Ask my teacher" bookmark** on every question builds a *My questions* list the
  student can show the teacher in class.
- Every question in a pool is used before any repeats.
- Topics are listed and built **in lesson order**.
- Top bar on every screen: back, title, My questions, Settings.
- Progress is saved on the device only. Logins come later — `app-src/src/lib/storage.js`
  is the only file that should need to change.
- Name: "Business English in Doses — Practice makes Perfect!", shown as **BizEng** on a
  phone. The icon is a placeholder until the owner sends the course logo.
- **The site does not link to the app yet.** Don't add a link until asked.

### Writing question content

Content lives in `app-src/src/data/`, one file per topic, listed in `topics.js`.

- **24 questions per activity type, per topic.**
- Contexts: business, work, office life, meetings, HR. Wide variety of situations.
- Sentences must be **realistic and natural** — what people actually say — but
  grammatically correct. Never robotic.
- **Every distractor must be definitely wrong.** A grammatical alternative that merely
  means something different is not a valid distractor.
- **Matching definitions must not be swappable** with any other definition in the topic,
  since any four can appear together.
- **Word order:** if the same chips can build a second correct sentence, add it to
  `alternatives`. Attached punctuation often rules this out.
- **Clues are short hints that never contain the answer.** Point at where to look
  ("Look at the preposition", "What form follows 'involve'?"), never at what's right.
  Aim for under 70 characters.
- Right/wrong sets should stay balanced between correct and incorrect sentences.

Before committing content, run `node tools/check-content.js` in `app-src`. It catches
answers missing from options, duplicate IDs, swappable matching definitions,
unbuildable word-order alternatives, and clues that leak their answer.

`node tools/make-review-page.js` produces a proofreading page of every question, for the
owner to read on a phone.

**Both tools are hardcoded to `lesson1.js`** — generalise them when topic 2 is added.
